# General Instructions

- Prefer simplicity and readability over cleverness
- Write descriptive commit messages (imperative mood, max 72 chars per line)
- Keep functions small and focused — single responsibility
- Use meaningful variable names, avoid abbreviations
- Add comments for "why", not "what"
- Prefer plain text / Markdown for documentation
- Don't commit generated files, binaries, or secrets
